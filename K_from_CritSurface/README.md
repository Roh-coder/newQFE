# K_from_CritSurface — Grid Search with Pre-Computed β_c Surface

Find the critical anisotropic couplings (k₁, k₂, k₃) of the 2D Ising model
on a triangular lattice by matching the two-point function to a reference,
using a **pre-computed β_c(r₁, r₂) surface** to eliminate the expensive
per-point susceptibility scan.

Sister package to `K_from_TwoPoint_standalone`.  Shares the same C++ simulator,
reference data, and cost functions, but replaces the inner-loop β_c finder
with a smooth FEM lookup.

---

## Motivation

In `K_from_TwoPoint_standalone`, each grid-point evaluation during the
optimization has two parts:

1. **Find β_c** — an MC susceptibility scan (GC3, 3-pass Gram-Charlier) to
   locate the critical temperature for the test couplings (r₁, r₂).
2. **Production run** — a long MC run at the found β_c, followed by cost
   evaluation (Z² boundary-slice matching).

From extensive diagnostics (30 trials × 5 methods), we know:

| Problem | Impact |
|---------|--------|
| β_c scan is ~60% of wall time per grid point | 6 levels × 25 points × ~100s scan = ~4 hours wasted |
| β_c finder jitter (σ ≈ 0.0007) is the **dominant noise source** | ~50% of Z² cost variance comes from β_c jitter |
| Jitter causes random cost fluctuations that mislead the grid search | Can pick wrong "best" point, wasting refinement levels |

**Key insight**: for a given lattice geometry (Lx, Ly, Tx, Ty), the critical
surface β_c(r₁, r₂) is a smooth, deterministic function.  We can measure it
once on a preparatory grid and interpolate forever after.

---

## How it works

### Phase 1: Build the β_c surface (one-time cost)

For a chosen lattice geometry and a region of (r₁, r₂) space, run MC
susceptibility scans on a regular grid:

```
r₂ ↑
   │  ●───●───●───●───●
   │  │ ╲ │ ╲ │ ╲ │ ╲ │
   │  ●───●───●───●───●      ● = MC scan point
   │  │ ╲ │ ╲ │ ╲ │ ╲ │      ─ = triangulated mesh
   │  ●───●───●───●───●
   │  │ ╲ │ ╲ │ ╲ │ ╲ │
   │  ●───●───●───●───●
   └──────────────────────→ r₁
```

At each grid point, the full GC3 β_c finder runs and records
β_c(r₁, r₂) ± uncertainty.  This is expensive (~100s per point at standard
statistics), but is done **once per geometry** and amortized across all
subsequent optimization runs.

The grid is Delaunay-triangulated and a piecewise-linear (P1 finite element)
interpolant is built over the triangulation.  This gives a continuous,
smooth β_c surface with no extrapolation artifacts inside the convex hull.

### Phase 2: Optimize using the surface

The grid search is identical to `K_from_TwoPoint_standalone` except that
the β_c finder call is replaced by a single surface lookup:

```python
# OLD (K_from_TwoPoint_standalone): ~100s per point, noisy
beta_c = find_beta_gc3(Lx, Ly, Tx, Ty, k1, k2, k3, beta_guess, scan_dir)

# NEW (K_from_CritSurface): instant, deterministic
beta_c = surface(r1, r2)
```

Benefits:
- **~60% faster** per grid point (only the production run remains)
- **Zero β_c jitter** — the interpolated surface is deterministic
- **All cost variance is pure MC noise** — the 50/50 split (β_c jitter vs
  MC noise) collapses to 100% MC noise, which averages down cleanly
  with more trajectories
- **Better grid refinement** — with deterministic β_c, the same physical
  point always gets the same β_c, so the cost landscape is smoother and
  the grid search converges more reliably

## Quick start

### 1. Prerequisites

- Working build of `K_from_TwoPoint_standalone` (see its README):
  ```bash
  cd ../K_from_TwoPoint_standalone && make
  ```
- Python 3.8+ with numpy, scipy, matplotlib:
  ```bash
  pip install numpy scipy matplotlib
  ```
- A reference dataset (either bundled 32×32 or generate your own)

### 2. Build the β_c surface

Edit the CONFIG section in `build_betac_surface.py` to match your geometry:

```python
Lx, Ly = 32, 32
Tx, Ty = 0, 0
R1_LO, R1_HI = 0.5, 2.5    # r₁ range to cover
R2_LO, R2_HI = 0.5, 2.5    # r₂ range
N_R1, N_R2   = 11, 11       # 11×11 = 121 scan points
```

Then run:

```bash
python build_betac_surface.py
```

This takes a while (121 points × ~2 min each ≈ 4 hours for standard stats).
Progress is saved incrementally — you can interrupt and resume.  The output
is `betac_surfaces/surface_32x32_T0x0.json`.

**Tip**: For a quick test, use a coarser grid (N_R1=N_R2=5 → 25 points)
and lower statistics:

```python
N_TRAJ_SCAN_COARSE = 10000
N_TRAJ_SCAN_FINE   = 20000
N_R1, N_R2 = 5, 5
```

### 3. Inspect the surface

```bash
python betac_surface.py betac_surfaces/surface_32x32_T0x0.json --plot
```

This prints a summary and saves a 2-panel plot (data + interpolated surface).

Query a specific point:

```bash
python betac_surface.py betac_surfaces/surface_32x32_T0x0.json --r1 1.0 --r2 1.0
```

### 4. Run the optimization

Edit `run_grid_search.py` to point to your surface file:

```python
BETAC_SURFACE = "betac_surfaces/surface_32x32_T0x0.json"
```

Then run:

```bash
python run_grid_search.py
```

Each grid point now prints `(LUT)` instead of the scan timing:

```
  [L0_i2_j2] r1=1.500000 r2=1.500000: β_c=0.21285714 (LUT)  Z²=45.12 (12s)
```

Compare the `(12s)` with the old `(112s)` — the scan overhead is eliminated.

## Surface file format

The JSON surface file has this structure:

```json
{
  "Lx": 32, "Ly": 32, "Tx": 0, "Ty": 0,
  "r1_vals": [0.5, 0.7, 0.9, ...],
  "r2_vals": [0.5, 0.7, 0.9, ...],
  "n_r1": 11, "n_r2": 11,
  "n_traj_scan_coarse": 30000,
  "n_traj_scan_fine": 60000,
  "points": [
    {"r1": 0.5, "r2": 0.5, "beta_c": 0.18234567},
    {"r1": 0.5, "r2": 0.7, "beta_c": 0.19456789},
    ...
  ]
}
```

The `BetacSurface` class loads this, builds a Delaunay triangulation of the
(r₁, r₂) points, and provides piecewise-linear interpolation.  Points
outside the convex hull fall back to nearest-neighbor extrapolation with a
warning.

## When to rebuild the surface

You need a new surface when:
- **Lattice geometry changes** (different Lx, Ly, Tx, Ty)
- **You want to search a different (r₁, r₂) region** not covered by the
  existing surface
- **You want higher accuracy** (denser grid, more MC statistics per point)

You do **not** need a new surface when:
- Changing the reference data (the surface is β_c of the test lattice, not
  the reference)
- Changing the cost function (Z² vs Z⁴ etc.)
- Changing the grid search parameters (half-span, N_GRID, etc.)
- Changing the production statistics (N_TRAJ_PROD)

## Comparison with K_from_TwoPoint_standalone

| Aspect | K_from_TwoPoint_standalone | K_from_CritSurface |
|--------|---------------------------|-------------------|
| β_c method | GC3 scan per grid point (~100s) | LUT interpolation (instant) |
| β_c noise | σ ≈ 0.0007 (dominant noise source) | Zero (deterministic) |
| Cost variance | ~50% from β_c, ~50% from MC | 100% from MC (averages cleanly) |
| Wall time per point | ~120s (scan + production) | ~15s (production only) |
| Setup cost | None | One-time surface build (~4h) |
| Amortized cost | Always pay scan | Surface reused across all runs |

**Break-even**: if you plan to evaluate more than ~30 grid points on the
same geometry (2 levels × 25 points), the surface approach is already
faster in total.  For multi-run campaigns (stability tests, parameter
sweeps), the savings are dramatic.

## Surface resolution guidelines

| Search region | Grid density | Reason |
|---------------|-------------|--------|
| ±0.5 around expected answer | 11×11 minimum | Good interpolation accuracy |
| ±1.0 (wide initial search) | 15×15 | Need more points for larger domain |
| Narrow refinement (±0.1) | 7×7 sufficient | Surface is nearly linear locally |
| Cross-geometry (4-5-6 etc.) | 11×11 on the test geometry | Surface depends on test lattice only |

The β_c surface is smooth (nearly linear in most regions), so even a
relatively coarse grid (11×11) gives interpolation errors much smaller
than the MC production noise.  You can verify by comparing a few
surface-interpolated β_c values against direct GC3 scans.

## Physics background

The 2D triangular Ising model with couplings (k₁, k₂, k₃) has an exact
critical condition:

$$\sinh(2\beta k_1)\sinh(2\beta k_2) + \sinh(2\beta k_2)\sinh(2\beta k_3) + \sinh(2\beta k_3)\sinh(2\beta k_1) = 1$$

For the equilateral case (k₁ = k₂ = k₃ = K), this gives the well-known
β_c K = ln(3)/4.  For general anisotropic couplings, the equation is
transcendental but can be solved numerically.

However, this exact condition applies only in the **thermodynamic limit**
(infinite lattice).  On a finite lattice, the susceptibility peak is shifted
by O(1/L) finite-size corrections.  The MC susceptibility scan finds the
**finite-size pseudo-critical β_c** for the actual lattice being simulated,
which is what the optimizer needs for a fair comparison against the reference.

This is why we scan rather than solve analytically: the surface must capture
the actual finite-size β_c on the (Lx × Ly) lattice, not the infinite-volume
result.

## Troubleshooting

**"β_c surface not found"**
Run `build_betac_surface.py` first.

**"outside the surface domain" warnings**
The grid search moved outside the (r₁, r₂) region covered by the surface.
Either widen R1_LO/R1_HI/R2_LO/R2_HI in `build_betac_surface.py` and
rebuild, or narrow the HALF_SPAN in `run_grid_search.py`.

**Surface seems inaccurate**
Run a few verification scans (pick random (r₁, r₂) points, run full GC3
scans, compare against the surface interpolation).  If the errors are
larger than expected, increase the surface grid density or MC statistics.

**"simulator not found"**
Build the simulator in the sister package:
```bash
cd ../K_from_TwoPoint_standalone && make
```
