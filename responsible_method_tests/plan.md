# Raw Manifold Campaign Plan

This plan defines the first raw-data campaign for the continuum-manifold check.
The scope is deliberately narrow: generate raw all-to-all datasets and pointwise
continuum extrapolations for the `1-1-1` and `4-5-6` targets, together with the
matching modular-theta solution sampled on the same normalized coordinate sets.

## Objective

Produce two benchmark manifests:

- `1-1-1` control geometry
- `4-5-6` anisotropic geometry

For each benchmark, generate:

- twisted-lattice raw all-to-all data across an integer-multiple size family
- untwisted-lattice raw all-to-all data across an integer-multiple size family
- pointwise finite-size extrapolation for every point on the smallest lattice
- modular solution values from Jacobi theta functions at the same normalized
  coordinates

The result should be raw comparison-ready data, not a finished statistical
claim. Statistical scoring and model selection will be a separate next step.

## Design Choice: Exact Criticality

For this campaign the simulations will run at exact criticality rather than
using a beta-finder workflow.

Reason:

- `1-1-1` has the exact triangular-lattice critical point
  `beta_c = ln(3) / 4 = 0.274653072167027` for `k1 = k2 = k3 = 1`.
- `4-5-6` on the untwisted anisotropic lattice has the exact ratios
  `r1 = 5.065231170850374`, `r2 = 7.742930488974055`, with
  `beta_c = ln(3 / sqrt(7)) / 2 = 0.062828607070227` for `k3 = 1`.
- The twisted `4-5-6` realization uses isotropic couplings on the twisted
  geometry, so its exact critical point is again `beta_c = ln(3) / 4`.

This isolates the finite-size scaling of the correlator manifold from any noise
or bias associated with pseudo-critical beta estimation.

## Benchmark Families

### 1. `1-1-1`

Target modular geometry:

- use the equilateral torus generated by `(Lx, Ly, Tx, Ty) = (12, 12, 0, 0)`

Twisted-lattice family:

- geometries `(12,12,0,0)`, `(24,24,0,0)`, `(36,36,0,0)`, `(48,48,0,0)`,
  `(72,72,0,0)`, `(96,96,0,0)`
- couplings `k1 = k2 = k3 = 1`
- exact `beta = 0.274653072167027`

Untwisted-lattice family:

- geometries `(12,12,0,0)`, `(24,24,0,0)`, `(36,36,0,0)`, `(48,48,0,0)`,
  `(72,72,0,0)`, `(96,96,0,0)`
- couplings `k1 = k2 = k3 = 1`
- exact `beta = 0.274653072167027`

Smallest-lattice point count:

- `12 x 12 = 144` raw lattice points, so the comparison set remains above 100
  points even after excluding the modular singularity at the origin.

### 2. `4-5-6`

Target modular geometry:

- use the twisted torus generated by `(Lx, Ly, Tx, Ty) = (13, 16, -3, 3)`

Twisted-lattice family:

- geometries `1x`, `2x`, `3x`, `4x` scaled copies of `(13,16,-3,3)`
- explicitly: `(13,16,-3,3)`, `(26,32,-6,6)`, `(39,48,-9,9)`,
  `(52,64,-12,12)`
- couplings `k1 = k2 = k3 = 1`
- exact `beta = 0.274653072167027`

Untwisted-lattice family:

- geometries `(16,16,0,0)`, `(32,32,0,0)`, `(48,48,0,0)`, `(64,64,0,0)`
- couplings `k3 = 1`, `k1 / k3 = 5.065231170850374`,
  `k2 / k3 = 7.742930488974055`
- exact `beta = 0.062828607070227`

Smallest-lattice point count:

- twisted smallest cell has `Lx * Ly + Tx * Ty = 13 * 16 - 9 = 199` points
- untwisted smallest cell has `16 x 16 = 256` points

Both therefore supply more than 100 comparison points to the modular solution.

## Finite-Size Scaling Rule

The continuum extrapolation will be done pointwise for every point on the
smallest lattice of each family.

Operationally:

1. Take the smallest lattice as the master point set.
2. For each enlarged lattice, match the same normalized cell coordinate by
   scaling the lattice displacement integers `(m, n)` by the same enlargement
   factor.
3. Fit the connected correlator at each master point as a function of `1 / s`,
   where `s` is the integer enlargement factor relative to the smallest lattice.
4. Save both the raw size-family data and the continuum intercept.

The finite-size scaling is therefore applied to all smallest-lattice points, not
just to selected line cuts or channel samples.

## Modular-Theta Data

For each benchmark and each lattice method, the modular solution will be
sampled on the same normalized coordinates used by that method's smallest
lattice point set.

Saved outputs will include:

- raw modular shape values from the Jacobi-theta formula
- the corresponding normalized torus coordinates
- a simple weighted amplitude fit aligning the modular shape to the lattice
  continuum data for convenience

The raw modular shape will remain the primary reference object.

## Output Products

The campaign will write under one run tag in `responsible_method_tests/results/`.

Per benchmark:

- `manifest_geometry_111.json` or `manifest_geometry_456.json`
- one family manifest for `twisted`
- one family manifest for `untwisted`
- copied raw all-to-all `.dat` files for every size
- metadata JSON for every size
- `smallest_lattice_points.dat`
- `pointwise_raw.dat`
- `pointwise_continuum.dat`
- `modular_raw.dat`
- `modular_aligned.dat`
- `modular_alignment.json`

## Immediate Execution Rule

This campaign is for raw data production only. After the manifests and raw data
exist, the next stage will be the statistical analysis of:

- lattice-vs-modular agreement
- twisted-vs-untwisted agreement
- pointwise uncertainty structure
- whether the current size families are already discriminating enough or need to
  be extended
