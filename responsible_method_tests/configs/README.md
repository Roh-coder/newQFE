# Configs

This folder is for small, explicit campaign specs rather than large production
configs.

## Intended Use

- Keep one top-level JSON file per validation campaign.
- Point each benchmark entry at the modular source, twisted manifest, and
  anisotropic manifest that should be compared.
- Record the deformation stencil and pass/fail thresholds alongside the paths.

## Relationship To Existing Workflows

- The twisted and untwisted lattice data can continue to be generated by the
  existing workflow directories in this repository.
- This folder should only store the lightweight specs that say which completed
  outputs belong to a validation benchmark.
- The starter file here is intentionally machine-readable so that later scripts
  can consume it directly.

## Starter File

- `campaign_template.json`: first-pass campaign spec with three benchmark cases
  and provisional thresholds.
